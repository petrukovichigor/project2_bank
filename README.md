# Учебный проект: Консольное приложение «Банк»

Реализация консольного приложения на C++ с использованием объектно-ориентированного программирования (ООП), демонстрирующего работу системы управления банковскими счетами.

## 📌 Суть проекта (Вариант №20)

Цель работы — создать систему автоматизации банка, которая позволяет управлять каталогом доступных типов счетов и собирать их в единую структуру банка с возможностью фильтрации, поиска и валидации ограничений.

### Архитектура и структура классов:
*   **Базовый абстрактный класс / Интерфейс:** `BaseAccount` (Базовый счет).
*   **Классы-наследники (типы счетов):**
    *   `DebitAccount` (Дебетовый счет)
    *   `CreditAccount` (Кредитный счет)
    *   `DepositAccount` (Депозитный счет)
*   **Класс Каталога:** `AccountCatalog` — каталог доступных элементов.
*   **Собирательный класс:** `Bank` — класс, объединяющий счета в единую систему.

## 🛠️ Функциональные требования к программе

### 1. Главное меню консоли
Программа должна иметь текстовый интерфейс со следующей структурой меню:

*   **1. Каталог предметов**
    *   1.1 Показать все доступные элементы
    *   1.2 Найти элемент по критериям
    *   1.3 Добавить элемент в каталог *(опционально)*
    *   1.4 Удалить элемент из каталога *(опционально)*
*   **2. Сборка объекта (Банк)**
    *   2.1 Показать текущую сборку счетов
    *   2.2 Добавить счет из каталога в сборку
    *   2.3 Удалить счет из сборки
    *   2.4 Применить сортировку **по балансу счетов**
    *   2.5 Поиск внутри сборки **по владельцу счета**
*   **3. Проверки и ограничения**
    *   3.1 Проверить соответствие ограничениям (**по общему числу счетов**)
    *   3.2 Показать отчёт о нарушениях лимитов
*   **4. Файловые операции**
    *   4.1 Сохранить каталог и сборку в файл
    *   4.2 Загрузить каталог и сборку из файла
*   **5. Дополнительная функция** (Реализуется по согласованию/комментарию в коде, например: расчет начисленных процентов по депозиту или комиссий за обслуживание)
*   **6. Выход**

## 📐 Критерии оценивания и технические требования (100 баллов)

*   **Проектирование и ООП (15 баллов):** Корректное выделение интерфейсов и использование абстрактного базового класса.
*   **Наследование и полиморфизм (12 баллов):** Логичное применение связей между классами счетов.
*   **Класс каталога (10 баллов):** Реализация логики `AccountCatalog`.
*   **Собирательный класс (12 баллов):** Контроль добавления и удаления элементов в банке.
*   **Ограничения (10 баллов):** Валидация лимита на максимальное или минимальное количество открытых счетов.
*   **Сортировка и поиск (10 баллов):** Быстрая сортировка по балансу и гибкий поиск по владельцу.
*   **Исключения (8 баллов):** Обработка неверного ввода пользователя и превышения лимитов (`try-catch`).
*   **Файлы (8 баллов):** Чтение и запись структуры данных в текстовый/бинарный файл.
*   **Доп. функция (8 баллов):** Реализация и документирование уникального метода для банковской сферы.
*   **Чистота кода (7 баллов):** Читаемый код, комментарии, отсутствие "магических чисел".
